# numerics-physics-b

## Summary
SoPlasma is an OpenFOAM-v2412 library suite: 15 shared libraries under /home/kkourtza/soplasma-scratch/src (profilers, constants, numerics, numerics/newtonSolverPETSc, electromagnetics, 8 plasmaModels, bcs, tools) plus 3 solvers and 12 utilities under src/applications. Physics is expressed in OpenFOAM's own idiom (fvm::/fvc::, GeometricField with real dimensionSets, dictionary + runTime selection tables) per governing directive C1; a third-party library is confined behind a thin mechanical boundary, of which src/numerics/newtonSolverPETSc/snesBridge.H is the worked example. The dominant defect classes here are NOT physics bugs: they are (1) partial rebuilds against a changed header ABI producing phantom SEGVs in libraries never edited, (2) MPI collectives placed behind guards on local patch size, (3) raw `break` out of pimple.loop() voiding the finalIter contract, (4) solution state that is not restorable on a discarded timestep, and (5) missing per-species fvSchemes entries that are fatal lookups, not fallbacks. Each has a measured cost on record and a cheap detector. The single most important operational fact discovered in this pass: `./Allwmake` is NOT a full build — `src/models/plasmaModels/Allwmake` builds only 4 of 8 model directories — so `./build-all.sh` is the only correct build command.

## Facts

### `./Allwmake` is NOT a full build and silently skips four libraries. `src/models/plasmaModels/Allwmake` contains exactly four wmake lines (genericPlasmaProperties, photoionization, plasmaSpecies, plasmaTransport) while the directory holds EIGHT model dirs — plasmaBoltzmann, plasmaChemistry, plasmaEnergy and plasmaReactionRates are never built by it. `src/applications/Allwmake` builds 3 solvers + 1 utility out of ~15 application dirs. The root `Allwmake`'s `wmake libso src/numerics` builds libplasmaNumerics only and never touches src/numerics/newtonSolverPETSc. All these scripts use `set -e` and print 'Build complete.' regardless.
**Evidence:** /home/kkourtza/soplasma-scratch/src/models/plasmaModels/Allwmake (22 lines, 4 wmake lines, verified by wc -l + grep -c wmake against `ls -d */` showing 8 dirs); /home/kkourtza/soplasma-scratch/src/applications/Allwmake; /home/kkourtza/soplasma-scratch/Allwmake line 'wmake libso src/numerics'

**Rule:** NEVER build with `./Allwmake`, `wmake` in a subdirectory, or `wmake libso src/numerics`. The only correct build is `cd /home/kkourtza/soplasma-scratch && ./build-all.sh`, whose BUILD_DIRS array has 31 entries (verified count) and whose coverage check fails the build if any src/applications dir with a Make/ is in neither BUILD_DIRS nor SKIP_DIRS.

**Cost:** This is the previously-unidentified root cause of memory `allwmake-can-silently-skip-a-changed-directory.md` (2026-09-08): `FORCE=1 ./Allwmake` exited 0, libplasmaEnergy.so's mtime was UNCHANGED after editing localEnergyEnergyModel.H/.C, while libplasmaProperties.so and libplasmaTransport.so DID rebuild in the same pass. That is exactly the covered/uncovered split of the Allwmake list — plasmaEnergy is not in it, the other two are. The memory records 'ROOT CAUSE NOT IDENTIFIED'; it is identified here.


### Adding a VIRTUAL to a shared header is an ABI change: it shifts every later vtable slot, so libraries not rebuilt call the wrong slot. Presents as a startup SEGV that looks like a physics bug.
**Evidence:** /home/kkourtza/soplasma-scratch/docs/CAPABILITIES.md:195-198 verbatim: '**Adding a VIRTUAL to a shared header is an ABI change.** It shifts every later vtable slot; rebuilding only the changed library leaves the others calling the wrong slots, which presents as a startup SEGV that looks like a physics bug. Rebuild everything (`./build-all.sh`).' Worked example: commit dfb4be6 (2026-09-11) hoisted updateDerivedFields() to a PURE virtual on electromagneticsModel; its message records 'VERIFIED: BUILD-COMPLETE across all 31 components (a pure virtual is a vtable change, so everything was rebuilt)'. build-all.sh's own header comment records the failure mode dated 2026-09-10: libplasmaNewtonSolverPETSc 'goes STALE silently and segfaults against a changed library ABI, which is exactly what happened on 2026-09-10 after a new virtual was added to plasmaTransportModel'.

**Rule:** After editing ANY .H that declares or inherits virtuals, or any .H whose class is included across libraries, run `./build-all.sh` in full and require the literal string `BUILD-COMPLETE` in its stdout. Never conclude anything from a run made on a partial rebuild.

**Cost:** Startup SEGV misdiagnosed as physics; on 2026-09-10 it took out libplasmaNewtonSolverPETSc, a library that is dlopen'd at runtime so nothing links it and nothing warns.


### Adding MEMBERS to a widely-included class's header is the same ABI trap by a different mechanism: it changes object size and every subsequent member offset, so a library compiled against the old layout reads garbage.
**Evidence:** /home/kkourtza/soplasma-scratch/src/models/plasmaModels/plasmaSpecies/plasmaSpecies.C:1290-1297 verbatim in-source comment: 'Adding members to plasmaSpecies.H changes the CLASS LAYOUT, and plasmaSpecies is included across the tree ... On 2026-09-08 doing exactly that segfaulted every case: wmake rebuilt the solver but left libplasmaEnergy compiled against the old layout, so it read garbage. A DIAGNOSTIC MUST NOT CHANGE A WIDELY-INCLUDED CLASS'S ABI.' Fix used there: `static List<scalar> negWorst_;` file-local statics instead of class members. Earlier instance: memory openfoam-abi-partial-rebuild.md (2026-08-13) — adding TgasField_, thermo_, bgThermo_, bgNames_, bgX_, kappaGas_ to plasmaTransport.H produced a bad_alloc in soPlasmaFoam AND a segfault in plasmaTimeControl::adjustDeltaT inside libplasmaTools, a library never edited all session.

**Rule:** For a DIAGNOSTIC or counter, prefer file-local `static` state in the .C over a new member in a widely-included .H (there is one plasmaSpecies per process, so it is equivalent). If a member is genuinely needed, full `./build-all.sh`. Partial rebuilds are fine for .C-only edits, never for .H layout or virtual changes.


### Build exit status is not evidence a library rebuilt. Allwmake/wmake can exit 0 with a .so mtime older than the .C mtime, and `./build-all.sh > log; echo $?` reports the ECHO's status, not the build's.
**Evidence:** memory allwmake-can-silently-skip-a-changed-directory.md: 'libplasmaEnergy.so's timestamp was UNCHANGED from before the edit, even though localEnergyEnergyModel.C's own mtime was newer than its existing .o file'. memory new-source-file-lninclude.md: 'read the build LOG, not the shell's exit status -- a `./build-all.sh > log; echo $?` reports the echo's status, and I called a `BUILD-FAILED` run passing because of it.' build-all.sh's own comment: 'This script printed "BUILD-COMPLETE" even when a component reported FAIL, and a whole session was spent grepping for that string as the build check.' (now fixed: it exits 1 with BUILD-FAILED).

**Rule:** After any build, run the mtime detector: `ls -la $FOAM_USER_LIBBIN/libplasma*.so` (=/home/kkourtza/OpenFOAM/kkourtza-v2412/platforms/linux64GccDPInt32Opt/lib) and confirm every library whose source you touched has a .so mtime NEWER than the edited source. If one is stale: `cd <that dir> && wclean && wmake libso .`, then a second full build-all.sh pass. Grep the build output for `BUILD-COMPLETE` AND for `BUILD-FAILED`/`UNCOVERED`.

**Cost:** memory rebuild-with-allwmake-not-piecemeal.md, 2026-09-07: a stale libplasmaTransport.so (which LINKS plasmaSpecies) raised a SIGFPE in mechanismSourceTerms; it was diagnosed as a pre-existing Scharfetter-Gummel defect, 'confirmed' by a control that ran against the SAME stale build, and reported to the user as a non-existent bug that then had to be retracted. 'A control experiment run against a stale binary is not a control.'


### A NEW source file is invisible to the build until `wmakeLnInclude -update` is run on its component, and the consumer's Make/options may additionally lack the include path. Both failures name the wrong file.
**Evidence:** memory new-source-file-lninclude.md: adding pressureUnits.H to src/constants/plasma/ gave 'fatal error: pressureUnits.H: No such file or directory' pointing at the INCLUDING header rather than the missing symlink; then failed again with the same message because plasmaBoltzmann's Make/options had no `-I$(SoPLASMA_SRC)/constants/lnInclude`. **Rule:** After adding a new .H/.C: (1) add the .C to that component's Make/files above the `LIB =` line; (2) `wmakeLnInclude -update src/<component>`; (3) `grep -n lnInclude <consumer>/Make/options` to confirm the `-I$(SoPLASMA_SRC)/<component>/lnInclude` path exists BEFORE building.


### The RTS pattern here is stock OpenFOAM, and a new model touches exactly five places. Concrete base classes: plasmaTransportModel, plasmaEnergyModel, emissionModel, photoionizationModel, electromagneticsModel, plasmaNewtonSolver, plus fvPatchField BCs.
**Evidence:** Transport: src/models/plasmaModels/plasmaTransport/plasmaTransportModels/plasmaTransportModel.H:97 `TypeName("plasmaTransportModel")`, :100-113 `declareRunTimeSelectionTable(autoPtr, plasmaTransportModel, dictionary, (const word& modelName, const dictionary& dict, const fvMesh& mesh, plasmaSpecies& species, const label specieIndex), (modelName, dict, mesh, species, specieIndex))`; plasmaTransportModel.C:46-75 `New()` does `dictionaryConstructorTable(modelName)` and on miss prints `dictionaryConstructorTablePtr_->sortedToc()`. Concrete: driftDiffusion.H:132 `TypeName("driftDiffusion")`; driftDiffusion.C:28-29 `defineTypeNameAndDebug(driftDiffusion, 0); addToRunTimeSelectionTable(plasmaTransportModel, driftDiffusion, dictionary);`; registered in Make/files line `plasmaTransportModels/driftDiffusion/driftDiffusion.C`. Energy: localEnergyEnergyModel.C:23-30 same pattern against plasmaEnergyModel, listed in src/models/plasmaModels/plasmaEnergy/Make/files. Newton: snesNewtonSolver.C:41 `addToRunTimeSelectionTable(plasmaNewtonSolver, snesNewtonSolver, dictionary);`.

**Rule:** A new model requires, in order: (1) <model>.H with `TypeName("<name>")` and the base's ctor signature; (2) <model>.C with `defineTypeNameAndDebug(<model>, 0);` + `addToRunTimeSelectionTable(<base>, <model>, dictionary);` and `#include "addToRunTimeSelectionTable.H"`; (3) the .C added to that library's Make/files; (4) `wmakeLnInclude -update` on the component; (5) `./build-all.sh`. Then verify reachability by grepping for a CALLER of every new virtual — compiling and registering is not evidence of wiring.


### Compiling and registering is NOT evidence a feature is reachable. Three declared-but-unreachable defects surfaced in one session, each invisible to the build.
**Evidence:** memory verify-wiring-not-just-compilation.md: `plasmaEnergy::eEqn()` was declared on the base, overridden by all four models, and CALLED BY NOBODY; committed as 'compiles and registers as energyModel localEnergy' and run on a 1.15M-cell case. `grep -rn "eEqn()" src/` takes five seconds and returned zero callers. memory declared-but-unreachable.md adds: an argList option declared and never fetched (an 18-run dt scan came back BIT-IDENTICAL), and `nEfloor_` defaulting to 1.0 guarding a quantity whose real floor is 1e13 — a guard unreachable by thirteen orders of magnitude.

**Rule:** Before committing or running new code: grep for a CALLER of every new virtual/method outside its own definition; grep for the READER of every new dictionary key (getOrDefault/lookup), not the declaration; for any new floor/cap/tolerance state in a comment which OTHER limit is already active on that quantity and whether the new one can ever bind. Bit-identical output after changing a knob is CONCLUSIVE that the knob is not wired — go read the code, do not re-run.

**Cost:** Three ~30-min validation runs plus a confident wrong diagnosis; the user's recorded complaint: 'these were MAJOR issues that you should have caught immediately and not by running validation cases.'


### PARALLEL: a collective (reduce/gSum/gMax/gMin/gAverage/returnReduce) must be reached by EVERY rank, the same number of times, in the same order. A local patch size() must never decide whether one runs. This is governing directive C1's third bullet (absorbed rule 31, commit 7b47378). Two spellings fail with two different symptoms.
**Evidence:** memory collective-behind-a-local-guard.md: `if (pf.size()) { gAverage(pf); }` DEADLOCKS under `simple` decomposition (whole electrode on one rank) but raises MPI_ERR_TRUNCATE under `scotch` (patch split, mismatch trips a later exchange). `reduce` downstream of `if (p.size() == 0) return` ran on a SUBSET of ranks and returned garbage, reporting `(D/delta + uEff)/(D/delta) = -1e+300` — 'It looked like a physics failure.' Two hours went into the wall-flux closure, rate tables and mesh before a per-rank trace showed the reduction was broken. In-source fixes carry the rule: electromagneticsModel.C:160-162 'THE REDUCTION IS UNCONDITIONAL. A rank holding no internal faces must still take part or the collective deadlocks -- rule 31'; plasmaSpecies.C:1287-1289 'THE REDUCTIONS ARE UNCONDITIONAL -- a rank whose subdomain happens to be clean must still take part'; soPlasmaFoam.C:476-477; snesNewtonSolver.C:59-60. 99 collective call sites exist under src/.

**Rule:** Hoist the collective OUT of the guard rather than guarding it harder (gAverage over an empty local field is well defined). Where a collective only found a global worst case for an error message, DELETE it — FatalErrorInFunction aborts the whole job in parallel and names the rank holding the bad face. Detector: per-rank `Pout` probes bracketing each construction (the rank that stops appearing is the one that diverged) — that found it in ONE build after reading the collectives got nowhere three times. Always test at least TWO decompositions (simple and scotch).

**Cost:** One full session, 2026-09-07. A parallel run that merely RUNS is not evidence it is right: verify against a serial reference (serial, np2 and np4 agreed to every printed digit on n_e,max, Te,max, Te,min).


### Anything resolving a CASE path must use `runTime.globalPath()`, not `runTime.path()` — the latter is `<case>/processorN` in parallel.
**Evidence:** src/models/electromagnetics/boundaryRoleLibrary/boundaryRoleLibrary.C:149-155: 'globalPath(), NOT path(). In a PARALLEL run Time::path() returns <case>/processorN, so every rank looked for its own copy of layer 1 and all of them died.' Same convention at plasmaCreateSpeciesFields.C:694, floatingElectrode.C:531, plasmaExternalCircuit.C:444, plasmaDischargeCurrent.C:537.

**Rule:** grep any new path construction for `time().path()` / `runTime.path()` and replace with `globalPath()`.


### `fvMatrix::residual()` is BROKEN in parallel for standalone use: it misreported by ~21 orders of magnitude. The replacement is explicit `fvc::` evaluation. `fvm::` + `.solve()` (an actual linear solve) is NOT implicated and remains fine, including as a preconditioner inner solve.
**Evidence:** memory fvmatrix-residual-broken-in-parallel-use-fvc-instead.md (2026-09-09). Unpreconditioned matrix-free JFNK using `fvScalarMatrix eqn(-D*fvm::laplacian(phi) + fvm::Sp(phi,phi) == fSource); eqn.residual()` converged (SNESConvergedReason positive) to a WRONG answer on 4 ranks (L2 error 0.408 vs manufactured solution) while giving L2 error 2.1648e-05 in serial — a ~20000x discrepancy, reproduced bit-for-bit across every independent fix (volume normalisation, a real PCSHELL, a duplicated MPI communicator, confirmed identical FormFunction call counts per rank). Decisive isolation: a NATIVE non-PETSc single call to eqn.residual() on the identical assembled matrix still reported ~1e-12, while `.solve()` on that SAME matrix needed 78 PCG iterations and 30 Picard sweeps walked it back to the correct answer. Python finite-difference ground truth read from each processor's own 0/ directory gave max|residual| ~ 6.5e9.

**Rule:** Compute any OUTER nonlinear residual, custom convergence check, or trustworthy-in-parallel diagnostic with explicit `fvc::` arithmetic on raw scalarFields. Never `fvm::` assembly followed by `.residual()`. Root cause below lduMatrix::residual()'s initMatrixInterfaces/updateMatrixInterfaces was NOT isolated — treat 'why' as open.


### There is no genuine explicit equivalent of `fvm::div(phi, n)` built from `fvc::interpolate` + `fvc::div`. The primitive is `fvc::flux(phi, n, schemeName)`.
**Evidence:** src/numerics/newtonSolverPETSc/snesNewtonSolver.C:493-507: 'phi_s is the CARRIER flux (mobility x field), not yet the total particle flux -- fvc::div(phi_s) alone would silently drop the n_s multiplication entirely (a real bug caught before this ever ran on a real case). fvc::flux(phi, n, name) is the genuine explicit equivalent of fvm::div(phi, n): it interpolates n to faces with the SAME scheme fvm::div would use.' Also docs/design/newton-outer-solver-design.md:695-710.

**Rule:** When hand-writing an explicit residual for a convection term, use `fvc::flux(phi, n, "div(phi_<s>,n_<s>)")` then `fvc::div(...)`, and pass the scheme name explicitly.


### A control object's exit path is part of its CONTRACT (governing directive C1, absorbed rule 29). `pimpleControl::loop()` guarantees ONE last iteration with `finalIter() == true` when residualControl converges, AND resets its iteration counter and converged flag in the loop() call that returns false. A raw `break` voids both.
**Evidence:** memory raw-break-skips-loop-contract.md + src/applications/solvers/soPlasmaFoam/soPlasmaFoam.C:653-683 and 800-830 (twin comment blocks in both Poisson branches): 'NO CUSTOM CONVERGENCE CRITERION HERE, AND NO `break`. ... If an early exit is ever genuinely needed here: set a flag and DRAIN the loop. Never `break`.' Measured on grubert2009_iset: step 1 ran PIMPLE iterations 1-5 with 4 charge updates, step 2 ran iterations 6-10 with 4 updates, step 3 reported 'converged in 10 iterations' with ZERO of either — the counter is CUMULATIVE across steps. Across two long Grubert runs 45-50% OF ALL TIMESTEPS executed ZERO correctors, so reported time ran 1.96-2.00x ahead of the physics. Introduced by commit 5924328 (2026-09-06), fixed by 4618a51 the same day.

**Rule:** Never leave `while (pimple.loop())` with break/return/goto. Before adding any early exit, `grep -n finalIter` in the loop body and decide explicitly what happens to each guarded call. Prefer making idempotent per-step updates UNCONDITIONAL: soPlasmaFoam.C:752 keeps `transport.solve(pimple.finalIter())` (which uses the flag legitimately) but species.updateChargeDensity() and transport.updateSurfaceCharge() are now called unconditionally every corrector.


### The measured cost of that one `break`: 151 charge-density updates in 364670 timesteps (0.04%). Poisson's source froze at the vacuum value while ion density grew three decades, and an entire day's 'runaway' physics investigation was chasing it.
**Evidence:** soPlasmaFoam.C:763-782 verbatim: 'MEASURED 2026-09-06, and it is the worst regression of the day: on the Grubert R1e9 arm, 151 charge-density updates in 364670 timesteps -- 0.04%. ... the field stayed at the VACUUM value (E/N = 1104 Td measured against V/L = 1106 Td, agreeing to 0.2%) while the ion density grew three decades.' Same numbers in src/tools/diagnostics/plasmaStepAudit/plasmaStepAudit.H:14-30.

**Rule:** After ANY loop-control change, verify with a per-step INVARIANT COUNT, not by inspection: one Info line per call, then compare `updates` against `timesteps` in the log. A field exactly equal to the vacuum solution in a run with accumulated space charge is a broken source term, not a result.


### The project ships a permanent registry for exactly this failure class: `plasmaStepAudit`, header-only, always on.
**Evidence:** /home/kkourtza/soplasma-scratch/src/tools/diagnostics/plasmaStepAudit/plasmaStepAudit.H — inline statics thisStep_/total_/required_; API `plasmaStepAudit::expect("updateChargeDensity")` at set-up, `plasmaStepAudit::record("...")` in the callee, `plasmaStepAudit::endStep(runTime.timeIndex())` once per step; fires '*** PER-STEP UPDATE DID NOT RUN: updateChargeDensity ***'. Header-only deliberately, because plasmaTools already depends on plasmaModels so a linked class could not be called from plasmaSpecies without a circular dependency. Called at soPlasmaFoam.C:1035-ish `plasmaStepAudit::endStep(...)` placed BEFORE `runTime.write()` so a step that skipped a required update fails before its fields land on disk.

**Rule:** Any new per-step update that MUST run once per timestep gets an `expect()` at construction and a `record()` in the callee. Cost is a hash lookup per call; it is left ON always because 'a diagnostic that has to be enabled is a diagnostic nobody has enabled.'


### THE STEP-DISCARD INVARIANT: every piece of solution state must be idempotent WITHIN a timestep, because `onNonConvergence retryStep` throws a step away and re-runs it at dt/2. There are exactly three legal ways to satisfy it, and a new energy model that forgets fails SILENTLY (the base is a no-op).
**Evidence:** src/applications/solvers/soPlasmaFoam/soPlasmaFoam.C:908-975 carries the full invariant as a comment block and the discard path itself: `transport.discardStep();` (:941), `if (energy) energy->discardStep();` (:942), `fe->discardStep()` for a floating electrode (:951), `r->discardStep()` on plasmaOuterRelaxation (:970), then `timeControl.prepareRetry(escalated); continue;`. The base no-op is src/models/plasmaModels/plasmaEnergy/plasmaEnergyModels/plasmaEnergyModel.H:171 `virtual void discardStep() {}`. plasmaEnergy.H:290-305 delegates to EVERY energy model unconditionally then T_gas, with the comment that the old early-return on solveGasEnergy_ meant such a case 'discarded NOTHING'. Overrides live at plasmaTransport.C:547, localEnergyEnergyModel.C:1875, floatingElectrode.C:450, plasmaOuterRelaxation.C:586. Memory step-discard-invariant.md records the user's standing instruction (2026-08-30).

**Rule:** A new field MUST be registered in whichever of these its owner is: src/models/plasmaModels/plasmaTransport/plasmaTransport/plasmaTransport.C::discardStep (species densities), src/models/plasmaModels/plasmaEnergy/plasmaEnergy/plasmaEnergy.H::discardStep + the owning model's override (n_eps, T_gas), src/models/electromagnetics/floatingElectrode/floatingElectrode.C::discardStep (accumulated charge), src/numerics/relaxation/plasmaOuterRelaxation/plasmaOuterRelaxation.C::discardStep (iterate history/counters). Decision rule: carries fvm::ddt -> restore (`f == f.oldTime(); f.correctBoundaryConditions();`); ACCUMULATES with += -> baseline it (`ev = ev_start + ...`, never `ev += ...`); per-pass counter -> zero it; cache -> key it on timeIndex.

**Cost:** n_eps was missed when retryStep was written — it lives in plasmaEnergy, not plasmaTransport — so a retried LMEA step re-solved with n_e at t^n and n_eps at the DISCARDED t^{n+1}, and meanE = n_eps/n_e mixed two instants. Measured: SIGFPE at step 6 after exactly ONE discard, zero non-convergences (~/co-sweep/retry-iso). It survived review because all four retryStep validation beds (co1.5-retry, -retry2ns, -retrytuned, -forceretry) are LFA and never exercise an electron-energy equation.


### C1 third-party confinement, worked example: snesBridge.H is a plain-types-only boundary. 'Mechanical only' means concretely: the only types crossing it are int/double/void*, C function pointers, and one POD struct of raw pointers; no OpenFOAM type and no PETSc type appears in the header; it contains zero physics decisions.
**Evidence:** /home/kkourtza/soplasma-scratch/src/numerics/newtonSolverPETSc/snesBridge.H, lines 1-6: 'Plain-types boundary between OpenFOAM (fvCFD.H) and PETSc (petscsnes.h). Neither header may be visible in the same translation unit as the other: PETSc's petscmath.h and OpenFOAM's own math overloads collide (ambiguous pow(), traced into OpenFOAM's error.H) once both are in scope anywhere in one TU. This header uses only int/double/void* so it can be included by both sides without pulling either heavy header across the boundary.' It exposes `void initPetsc()`, `void finalizePetsc()`, `void setPetscOptions(const char*)`, `typedef void (*ResidualCallback)(int n, const double* x, double* F, void* userData)`, `typedef void (*PCApplyCallback)(int n, const double* b, double* y, void* userData)`, `extern const double snesNoBound` (a sentinel chosen specifically so the OpenFOAM side never sees PETSC_NINFINITY), and `struct SnesPmatCOO { int n; const int* rows; const int* cols; const double* vals; int nTail; }`. The physics (residual assembly, the Knoll & Keyes preconditioner, the density lower bounds) all lives on the OpenFOAM side in snesNewtonSolver.C and is passed in as callbacks.

**Rule:** When wrapping any new third-party library: put ONLY POD types and function pointers in the boundary header, keep both heavy headers out of any shared translation unit, invent local sentinels rather than re-exporting the library's constants, and keep every physics decision on the OpenFOAM side. Do not let the third-party type system leak one level up.


### fvSchemes entries are named PER SPECIES and a missing one is a FATAL LOOKUP, not a fall-through to `default`. Under `outerSolver newton` FIVE regex catch-alls are required, because Newton assembles every species equation itself.
**Evidence:** /home/kkourtza/soplasma-scratch/tutorials/plasma/soPlasmaFoam/needleDBD/system/fvSchemes, verbatim, at these lines: :51 `"div\(phi_.*,n_.*\)"            $electronDriftDivScheme;` :67 `"laplacian\(D_.*,n_.*\)"        $electronDiffusionLaplacianScheme;` :104 `"interpolate\(n_.*\)"           linear;` :105 `"interpolate\(mu_.*\)"          $electronMobilityInterpolationScheme;` :106 `"interpolate\(D_.*\)"           $electronDiffusivityInterpolationScheme;` :136 `"snGrad\(n_.*\)"              corrected 0.33;`. docs/CAPABILITIES.md:577-582 names snGrad as 'A FIFTH fvSchemes catch-all' beyond the three the streamer beds needed (interpolate(mu_*), div(phi_*,n_*), laplacian(D_*,n_*)) — the fifth in the file is interpolate(D_*), and interpolate(n_*) is also present.

**Rule:** Any case run under `outerSolver newton` must carry, at minimum: "div\(phi_.*,n_.*\)", "laplacian\(D_.*,n_.*\)", "interpolate\(mu_.*\)", "interpolate\(D_.*\)" and "snGrad\(n_.*\)" — plus "interpolate\(n_.*\)". Also list BOTH Poisson laplacian forms (`laplacian((epsilon+(deltaT*electricalConductivity)),ePotential)` for semiImplicit and `laplacian(epsilon,ePotential)` for explicit), because listing one works until someone flips poissonScheme. An UNUSED entry costs nothing; a MISSING one is fatal.

**Cost:** needleDBD died after 545 residual evaluations on `Entry 'snGrad(n_N2p)' not found` (2026-09-11). A case whose ions were mobile died at step 1 on `laplacian(D_Ar2p,n_Ar2p)` because only the electron was enumerated. They fail one FAMILY at a time, minutes apart — so a case copied from a bed with immobile ions appears to work and then dies three times (docs/reference/fvSchemes-fvSolution.md:9-21).


### The convective flux is named `phi_<species>`, NOT `particleFlux_<species>` — the latter is the registered diagnostic FIELD the boundary conditions read.
**Evidence:** needleDBD system/fvSchemes:41-47 and docs/reference/fvSchemes-fvSolution.md:22-25: 'Guessing it costs a run.'

**Rule:** When adding an fvSchemes key for a new term, take the name from the actual error message (`Entry 'X' not found in YSchemes`), never from the field name.


### Scheme names are auto-derived from field names, so any operator applied to a RENAMED field (a Newton correction, a work field) needs the REAL field's key passed explicitly as the third argument.
**Evidence:** docs/design/newton-outer-solver-design.md:766-771: 'Scheme-name auto-derivation breaks on a renamed field. fvc::snGrad(dePotential) derives snGrad(d_ePotential), absent from fvSchemes. ### A coefficient that is exactly zero is not safe if it is harmonically interpolated. `immobile` returning zero mu/D is 0/0 on every face under `harmonic` interpolation; it is now 1e-30.
**Evidence:** docs/CAPABILITIES.md:201-211: 'the streamer beds interpolate mobility with harmonic (2ab/(a+b)) and diffusivity with Gauss harmonic corrected, so an identically-zero coefficient is 0/0 on every face. Commit a460d01 'Immobile mu/D: negligible, not zero -- harmonic interpolation divides'.

**Rule:** Never return an identically-zero transport coefficient. Return a negligible-but-normal value and state the ratio to a real value in the comment. Check what interpolation and what flux scheme will consume it.
